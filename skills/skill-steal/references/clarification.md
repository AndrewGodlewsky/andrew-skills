# Clarification and GT dependencies

Use the client-supplied selected GT installation identity. Resolve **grill-me**
for necessary clarification and **create-issue** when submission is intended,
preserving their enabled state. Both must permit model invocation. Missing,
disabled, shadowed or ambiguous dependencies are unavailable; do not substitute a
personal skill, arbitrary cache copy, repository copy or direct GitHub client.
Ask which installation is intended if identity is ambiguous. Do not install,
enable or edit dependencies implicitly.

When clarification is needed, load and follow the selected GT Grill Me through
the client's supported skill mechanism. Pass the original request, source
contract, compatibility conflicts, previous answers and unresolved decisions.
Let it conduct its existing interview, one question at a time with recommendations,
and wait for confirmed understanding. Preserve corrections and explicit deferrals.
A missing interview dependency, pause or unconfirmed core intent leaves a draft;
do not replace the interviewer. Record actual execution evidence without inventing
invocation telemetry when the client only supports loading instructions.

Keep an ordered record of exchanges: exact consequential user statements when
available, agent recommendations labeled as recommendations, answers, corrections,
confirmation and unanswered questions. Redact private details without losing
distinct requirements. Do not present agent summaries as quotations. Confirmation
of intent is separate from authorization to publish material.

For preparation, `intent` is the concise nonempty intent recap. `interview` has
exactly `status` and nonempty `text`. Use `recorded` for actual exchanges (including
explicit unresolved decisions), `none` when clear supplied material needed no
interview, or `unavailable` for genuinely missing history. Explain why none was
needed and preserve the supplied requirements, or label surviving summaries and
history gaps. Never invent an interview to fill this record.

A draft-only request does not require the delivery dependency or a GitHub preflight.
For delivery, read the selected Create Issue instructions and helper protocol,
then follow the bundled submission guide. Local check/preparation tools are
bundled here; they do not require invoking or locating Create Skills.
