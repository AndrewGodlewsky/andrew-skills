# Compact explanatory issue prose

Before final preview, any required approval and delivery-payload preparation,
assemble all authored content destined for the issue title, body and planned
comments, including material the delivery helper may later split into parts.
Complete the caller's privacy redactions first and retain this original for
comparison. Compression does not replace the caller's review or authority checks.

## Select eligible text

Select only explanatory prose written by the agent. Protect user quotes, answers,
corrections, intent recaps, requirements, specifications, acceptance criteria and
consequential approvals. Also protect proposed skill instructions, package files,
templates, examples intended for the skill, code, commands and exact evidence or
diagnostic output. Never edit package files as part of this pass.

Classify by purpose, not headings or Markdown formatting. Ordinary prose inside
a proposed SKILL.md is skill content; a requirement outside a code block is still
a requirement. In a mixed paragraph, isolate only clearly eligible spans and
keep surrounding protected text verbatim. Leave ambiguous spans unchanged.
If no eligible text remains, retain the original and report that no pass was needed.

## Apply the selected GT Caveman

Resolve the exposed, enabled **GT caveman** from the same client-selected GT
installation used for the other dependencies. Load its actual SKILL.md and use
its one-pass issue-prose edit with `lite` (the alias for `light`). Pass only the
identified eligible spans, with any necessary surrounding material explicitly
marked as protected context. Request replacement text for those spans only,
with the surrounding conversation's style left unchanged. Follow the loaded
instructions; do not imitate the style or substitute a personal copy or companion
skill. Instruction-based loading and following is sufficient unless the host
provides and requires a separate invocation operation.

An absent, disabled, shadowed, ambiguous or unreadable dependency, or an older
version without the one-pass capability, means skip compression. If the pass
fails, retain the original as well. Report the skipped pass and reason, then
continue through the caller's existing review and submission rules. Do not
install, enable, alter caches or retry using another copy. Preserve the caller's
security-stop rules; compression is not a reason to bypass a denial.

## Compare, preview and deliver

Insert returned replacements only into their identified eligible spans. Compare
every protected span against the retained original and restore any change.
Review eligible edits for preserved facts, attribution, uncertainty, negation,
conditions, technical terms, identifiers, numbers, units, links and relevant
context. Retain the original wherever meaning changes or clarity gets worse;
if the comparison cannot be completed reliably, retain the entire original and
report compression skipped. Keep the outcome accurate: applied, no eligible
text, or skipped with a reason; do not claim an invocation that did not occur.

For example, agent framing such as "The purpose of this section is to explain why
the check was not run." may become "This section explains why the check was not
run." A specification sentence such as "Only explanatory prose may be compressed."
stays verbatim, wherever it appears.

Use the reviewed text as input to the existing delivery helper. Its fixed headings,
indexes, hashes and package representations are not compression targets. Preview
the resulting exact title, body and planned comments using the caller's review
rules, then send that same plan. Never compress an approved or attempted plan.
Later material edits return to drafting and the caller's applicable review and
approval steps; they do not authorize replaying a previously attempted delivery.
