# Skill-map data and viewer

Data implemented for [#61](https://github.com/AndrewGodlewsky/andrew-skills/issues/61)
and the [production viewer](../skill-map.md) for
[#62](https://github.com/AndrewGodlewsky/andrew-skills/issues/62).
Persisted artifact generation/checks, CI and the normal AGENTS.md/CONTRIBUTING.md
maintenance workflow belong to #63. The throwaway presentation prototype is retired.

From the repository root, these commands read working files without writing:

```sh
node scripts/skill-map.mjs
node scripts/skill-map.mjs --impact skill:grill-me
node scripts/skill-map.mjs --impact file:scripts/intent-record.mjs
node scripts/skill-map-server.mjs
node --test scripts/skill-map.test.mjs scripts/skill-map-view.test.mjs
```

The first command emits the complete JSON analysis, including diagnostics and
`ready`. The impact commands emit potential callers and evidence paths, not
proven breakage. This diagnostic CLI does not enforce a failure exit code for
incomplete review; the read-only readiness command/CI integration belongs to #63.
Parse/load errors do fail. Do not treat exit zero as an assertion of readiness.

The server binds to loopback at `http://127.0.0.1:43854/` (`--port N` overrides
the port). It loads current files and records for each page/export request;
it neither writes files nor executes inspected code. One response uses one
consistent snapshot. `/data.json` and `/map.md` are deterministic exports;
`/text` is a server-rendered fallback. Source links show escaped current text
with line anchors and warn if the snapshot changed since the evidence link.
Binary resources must be inspected in a suitable local tool. Malformed record
envelopes produce an explicit load error; incomplete valid analyses still render.

`skill-map-view.mjs` exports `renderPage`, `renderMarkdown`, `viewState`,
`graphProjection` and `layoutGraph`. The simple graph includes all linked skills
and a selectable list of isolated skills. The expanded graph shows immediate
links around a selection; full caller paths remain in the side panel and the
table lists every discovered resource. Strongly connected components keep cyclic
layouts finite. Above 12 paths per caller, an explicit link reveals all enumerated
paths; the impact API's traversal limit stays visibly marked as incomplete.

The viewer needs no installed packages or external assets. Native links, forms
and disclosures work without JavaScript; the small script adds whole-row clicks,
automatic form submission and focus transfer. Stop the server with Ctrl+C.

## Data and API

[relationships.json](relationships.json) is authored repository metadata, not a
generated inventory. It contains explicit edges, generated-copy provenance,
reviewed exclusions and per-skill review attestations. Inventory is discovered
from the current `skills/` tree, including local additions and incomplete folders.
No skill header changes or runtime dependency on these files is required.

[skill-map.mjs](../../scripts/skill-map.mjs) exports:

- `readSkillMapFiles(root)`: read regular repository files into a path-to-Buffer
  Map; reject links and unsupported filesystem entries. No Git, network or
  inspected-resource execution. It reads skills, scripts, exporter and the guide;
  analysis fingerprints only package files and declared dependency/provenance
  inputs, not the generated map or its implementation.
- `analyzeSkillMap(files, records)`: return deterministic nodes, edges, evidence
  locations, candidates, provenance results, diagnostics and readiness. It does
  not modify files or certify reviews. A malformed envelope throws; individual
  invalid records become diagnostics while other known relationships stay visible.
- `scanCandidates(files, names, paths)`: suggest references for review. A candidate
  is a source/target pair with every detected occurrence and a full-source digest.
- `reverseImpact(map, target, options)`: simple skill-only impact by default;
  `{expanded: true}` includes resources and provenance. Selecting a skill in that
  mode also considers its owned resources. Returned paths identify the actual
  changed resource rather than inventing a skill invocation. Unique callers have
  all enumerated simple paths and conditions. Cycles terminate; the selected
  skill is excluded from its own caller count. A default 10,000 traversed-path
  limit returns `truncated: true` if reached; the viewer must display that limit.
- `sourceDigest(files, path)` and `expectedCopy(files, provenance)`: shared
  fingerprint and bounded, repository-specific build-transform evaluation.

IDs are `skill:<directory-name>` and `file:<repository-relative-path>`. Arrows
mean relies-on. `skill` edges are actual inter-skill use; `resource` edges are
instruction references/module use; `entry` connects a skill to its instructions;
`source` connects generated bytes to maintained inputs; `build` connects a copy
to its builder. Every authored dependency records conditions and source quotes.
Evidence locations are derived from a unique current match, not stored line
numbers. Missing or duplicate matches remain visibly stale/ambiguous.

Source reuse is distinct from runtime use. A transformed copy does not inherit
the original file's removed imports or links. Impact traversal follows runtime
references on the generated copy, and provenance/build inputs after a source
hop. For example, Skill Steal rewrites the creator submission guide's intent
link to its own clarification guide. It depends on the maintained submission
guide, but does not consume `scripts/intent-capture.md`. Both semantics have
regression coverage. Use the impact API rather than a naive transitive closure.

## Review and coverage

Initial audit: 17 skill packages, eight inter-skill dependencies and 51 generated
copies. All current candidates were classified with either explicit dependency
evidence or a reasoned exclusion. The dataset also includes Python module use
and the exporter's manifest-driven module loading that lexical import scanning
does not reconstruct. The two installation-target guides currently have no
declared maintained common source; identical text alone does not establish one.

The review digest covers the whole package inventory/contents, relevant shared
inputs/builders, dependency conditions/evidence, candidate identities,
exclusions and provenance declarations. Adding/deleting a file or changing
context outside a still-matching quote invalidates review. Inventory changes
re-scan existing instructions. A new skill starts pending even with no edges.
`reviewedSkillIndependent` means reviewed absence of **skill-to-skill**
dependencies, not absence of bundled resources or external prerequisites.

To update records, inspect the affected source and candidate occurrences,
repair/add edges or document exclusions, and inspect the new analysis. Only
after semantic review, explicitly record the corresponding skill node's
`sourceDigest` as its review `digest`, with reviewer identity and a useful note.
Exclusions bind their reason to the candidate's whole-source digest. Copying
hashes without reviewing content defeats this contract; no auto-accept command
is provided. Keep the actual review and checks in the issue carrying the change.

Recognized UTF-8 text formats and extensionless UTF-8 text without NULs normalize
CRLF to LF; other resources retain exact bytes. Paths are repository-relative
and ordered; no timestamps, absolute machine paths or clean-checkout requirement
enter fingerprints. Generated-copy comparisons use the documented text
transforms; existing bundle `--check` commands remain the byte-level authority.

## Limits

This is a dependency-focused audit, not a security or runtime-compatibility
audit. The graph covers repository skills/resources; host tools, Python/Node,
providers and arbitrary user-selected files are not graph nodes. Read source
instructions for those external prerequisites.

Scanning recognizes current skill names (hyphen/space/case variants), GT command
names and skill paths, inline Markdown links, relative JavaScript imports,
simple Python relative imports and selected code-span resource paths. It is not
a complete Markdown parser, language parser or semantic analyzer. Dynamic
loading, arbitrary aliases, reference-style Markdown and new build transforms
need explicit review/declarations. Code examples and negations remain candidates
until classified; their presence never creates an asserted edge by itself.

Maintained build transforms are explicitly supported rather than executing
arbitrary builders or package code. A new transform needs implementation and
tests. The readiness result proves current evidence/review consistency within
this model, not that no human or agent could have missed a prose dependency.
