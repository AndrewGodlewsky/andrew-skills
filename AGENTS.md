# Project instructions

## Skill authoring

Before adding or changing a skill, read [CONTRIBUTING.md](CONTRIBUTING.md), the
single current authoring guide. Follow its package/header rules, examples,
checklist and release workflow. Keep change-specific requests, expected results,
actual checks and exception rationale in one existing issue or PR and link that
record. Keep runtime instructions self-contained; generated skills must not
depend on repository-only authoring documents. Preserve the owner's separate
authorization requirements for commits, pushes, PRs, merges and other Git writes.
